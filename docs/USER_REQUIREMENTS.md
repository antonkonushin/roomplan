# Исходное задание и уточнения

Разработать web-прототип моделирования квартир/комнат, планирования мебели и фотореалистичной визуализации, который станет основой интеграции алгоритмов исследовательской команды. Исходники — https://github.com/antonkonushin/roomplan ; основной код Python, визуализация Three.js. Blueprint3D допустим, но не обязателен.

1. Начало с плана: (а) фотография/скан — базовое распознавание и запрос высоты потолка; (б) видео с телефона — заглушка реконструкции; (в) набор фотографий — заглушка multi-view реконструкции. В (б)/(в) выдавать дефолтный меблированный план, предусмотреть дальнейшее распознавание высоты/мебели. Оставить комментарии о подключении настоящих модулей. В (а) layout без мебели означает только стены.
2. Трёхмерный просмотр с вращением, перемещением, масштабированием, двумерный вид сверху с перемещением/масштабированием. Мебель и техника видны в обоих видах. Независимые слои для облаков точек, дополнительной информации, 3D bounding boxes мебели.
3. Уточнение размеров выбранных стен, включая длину и высоту, корректирует модель.
4. Каталог мебели по категориям, по два примера каждой категории. Размещение на полу, на других предметах и на стенах, перемещение по соответствующим поверхностям.
5. Кастомная мебель из фотографий. Подключение готового метода single-image reconstruction; расширение на multi-view в будущем.
6. Сохранение/загрузка проекта на компьютер пользователя, включая все исходные видео, снимки и модельные ресурсы.
7. Генерация видео прохода средствами обычной компьютерной графики; будущая возможность генеративного видео.
8. Красиво оформленный экспорт плана с мебелью для размещения в объявлениях.

## Уточнение пользователя 15.10.2026
Для реконструкции кастомных объектов выбран **локальный GPU-сервис; подключить позже**. Нельзя отправлять пользовательские фото во внешний inference API по умолчанию. До подключения сервиса отображать реальное состояние, сохранять источники и предусмотреть повторный запуск. Это принятая отсроченная интеграция, не дефект маскируемый под готовую реконструкцию.

## Gauntlet
Использовать субагентов builder/critic со свежим контекстом. Критики проверяют работающие результаты и реальные экспорты. Конкретные эталоны Floorplanner фиксируются в docs/quality-bar.md. Повторять улучшения и независимые сравнения без заранее заданного числа раундов; вести живую страницу /progress. Не объявлять победу по наличию кода или только тестам.
